# Changelog — v1.0.13

> **Note:** v1.0.13 was released in multiple OTA batches before a full binary build. The sections below reflect those batches in order.

---

## Batch 1 — Organizer tier limits, registration form, and My Tickets

Summary: registration form improvements and organizer tier limits. Pending RSVP cards now show the correct quantity and the customer-paid total (including service fee), the mobile checkout sheet matches what Stripe authorizes for any event with custom service fee settings, and a previously hidden pending RSVP scenario is fixed so every active request always shows up on the user's My Tickets page.

### Fixes

- Purchase Details exports now report the **base ticket price** (organizer-net, excluding service fee) instead of the buyer-paid amount, so the column reconciles directly with the dashboard's Total Revenue stat for the same event. The column is renamed to "Base Ticket Price" across both purchase and pending RSVP exports for clarity. Works correctly for both current Stripe orders (uses the stored base price) and legacy orders (reverse-extracted from the historical fee structure).
- Fixed the web `flme.co/qr-scanner` page rejecting signed-in users with a valid event access code if they weren't an organizer or admin of that event's organization — for example, a regular Flame account holder helping at the door, or an organizer signed into a different org. The validate-code endpoint now treats the access code itself as the credential, matching how the verify and check-in endpoints already worked, so anyone with a valid code can scan regardless of who they're signed in as. Previously these users hit a 403 "Insufficient permissions" or "You do not have access to this event's organization" error before the camera could open. The mobile public scanner was unaffected (no Flame session attached) — this was a web-only regression.
- Fixed a display inconsistency where a ticket tier that was fully claimed by pending RSVPs still appeared as "available" on the public event page. The page now stays in sync so attendees see the correct status. Attempting to request a ticket on a fully claimed tier was already blocked correctly — this was a display-only correction.
- Fixed a validation gap where an organizer could reduce a tier's capacity below its pending RSVP count when no sales had completed yet — the minimum quantity floor now applies as soon as any slots are claimed, whether by sales or pending RSVPs. Attempting to approve a pending RSVP after reducing capacity that way would have failed silently.
- Fixed the same gap in the web API — organizers editing tier capacity from the web dashboard can no longer set a quantity below the combined sold + pending RSVP count. The error message now lists the sold and pending counts separately so the organizer can see exactly why the floor exists.
- Fixed long tier names pushing the edit and delete buttons off the screen in the mobile event-management view — titles now truncate at two lines and the action buttons stay in place.
- Fixed tier availability details overflowing their container on the web organizer event-detail page at narrow browser widths — the layout now stacks cleanly at mobile viewport sizes, matching the organizer dashboard.
- Fixed a web organizer bug where disabling the registration form on an event that had archived fields would silently erase all archived field definitions — historical RSVP answer labels are now preserved even when the form is turned off.
- Fixed the registration form toggle on the web event edit page incorrectly showing as "on" when the form contained only archived fields — the toggle now reflects only active (non-archived) fields, so organizers see the correct state when reopening an event whose form was previously disabled.
- Fixed archiving a registration form field on mobile not persisting — the archived state showed briefly in the UI but was stripped from the save payload, so reopening the event showed the field as active again. The archive flag now round-trips correctly, and disabling a form on mobile preserves archived field definitions the same way it does on web (so historical RSVP answer labels survive a form being turned off). The form toggle on mobile also now correctly shows "off" when an event has only archived fields remaining.
- Fixed pending RSVP cards on My Tickets (web and mobile) showing the **wrong quantity**. A request for multiple tickets (e.g. 2 General Admission) used to display as a single card; the card now shows the correct number of requested tickets while pending. Once the organizer approves and the tickets are issued, the card continues to display the correct total quantity.
- Fixed pending RSVP cards on My Tickets (web and mobile) showing the **base ticket price** instead of the customer-paid total with service fee. Pending requests now display the same total the user agreed to at request time (e.g. `$55.99` for a $50 base ticket with the standard service fee), matching what is held on the card and what later appears on the issued ticket card.
- Fixed an "approved RSVP" card briefly appearing on My Tickets (web and mobile) with a dead-end "Buy" call-to-action during the short window between approval and ticket issuance. Approved RSVPs that haven't been issued yet now stay labeled as "Pending" so users never tap a button that goes nowhere.
- Fixed the mobile checkout sheet showing the **wrong total** for events with non-default service fee settings. Previously the sheet always estimated using the standard 10% + $0.99 markup, while the Stripe authorization used the event's actual service fee — for an event with a different fee configuration, the user could see one number on the sheet and another in their bank app. The sheet now reads each event's service fee directly from the event configuration, so the total shown to the user always matches what is authorized on the card. Web was unaffected because it already waits for the server total before displaying the breakdown.
- Fixed a case where a **new pending RSVP didn't appear on My Tickets** (web and mobile) when the user already had previously issued tickets for the same event and ticket type. For example: a user with 2 General Admission tickets from a past purchase who submitted a new request for 3 more saw only the old purchase, not the new pending request. Both now show as separate cards — one for the existing tickets, one for each pending request.
- Fixed the **stat counters on My Tickets** (web and mobile) showing the wrong totals for pending RSVPs. A request for 3 tickets used to render a card reading "Ticket QNT: 3" alongside a stat pill that said "Pending: 1". Pending and Total now sum the actual requested ticket counts, so the pill always agrees with the cards below it.
- Fixed the **stat cards on the mobile My Tickets screen** rendering with one card stretched to twice the width of the others after the previous "Ready to buy" tile was removed. The three cards (Total, Purchased, Pending) now sit in a single equally-sized row, matching the web layout.
- Fixed the **mobile Send Tickets → Send Free Ticket** flow not letting organizers choose which tier they were sending. The screen now mirrors the web version: search the recipient → pick the tier → choose a quantity (1–10) → Send. Previously mobile silently picked the first non-sold-out tier with no way to change it.
- Fixed the **complimentary ticket label** showing "Free" on mobile and "Complementary" on web (also a typo — the correct word is "Complimentary"). All surfaces — organizer's Sent list, user's My Tickets card, and the ticket detail QR view — now show **"Complimentary"** consistently. The user's My Tickets card previously showed `$0.00` next to a promo ticket's tier name; it now reads "Complimentary" so users can tell at a glance the ticket was given to them at no charge.
- Fixed **bank-transfer tickets in My Tickets and the ticket detail view showing the full price including the platform service fee**. Bank transfers are organizer-issued, off-platform payments and the platform fee does not apply — users now see only the base ticket price (which is what they actually owe the organizer). Affects both web and mobile.
- Fixed the **organizer's Sent list (web and mobile) showing prices like "$23.14" for a $25 bank-transfer ticket** — the screen was running every total through a legacy fee-extraction routine and inventing a markup that was never charged. Modern bank-transfer orders ($25, $20×10, $25×4, etc.) now render their actual base price; legacy bank-transfer rows from before the Stripe Connect migration still extract correctly.
- Fixed the **mobile bank-transfer tier dropdown showing a `$` prefix for non-USD events**. The dropdown now formats prices using the event's actual currency.

### Improvements

- Raised the cap on ticket tiers per event from **5 to 10** for organizers on web (create event, dashboard tiers view, event detail) and mobile (create-event tiers step and edit-tiers on existing events). The limit is driven by a shared `MAX_TICKET_TIERS_PER_EVENT` constant in `@project-flame/lib` so web and mobile stay aligned.
- Event creation (`POST /api/events`) now rejects payloads with more than 10 tiers in the `ticket_tiers` array; adding a tier (`POST /api/ticket-tiers`) returns a clear error if the event already has 10 tiers — previously the cap was UI-only and could be bypassed.
- Registration form fields can now be archived instead of deleted. Archived fields stay hidden from new registrants but still label historical RSVP answers in organizer detail views and exports, so "week-one only" questions can be retired without losing past data.
- Added an archive/unarchive toggle to the mobile form builder — archived cards dim with a caption explaining they are hidden from new registrations while previous answers stay visible.
- Registration form answers tied to archived fields now show an "(archived)" hint in mobile and web RSVP detail views, so organizers can tell at a glance which questions are no longer active.
- Archived fields are skipped by required-field validation when attendees submit an RSVP, so retired questions never block a new submission.
- Organizers can now edit the registration form from the web event-management page after publishing, not just during event creation. The builder on the edit screen is the same one used at creation and supports adding, editing, archiving, unarchiving, and removing fields on a live event.
- Sign in with Apple and Google now shows a single "By continuing you agree to our Terms of Service and Privacy Policy" disclaimer in place of the previous checkbox — one consent surface covers all authentication methods on the screen. Sign in with Apple now handles the case where Apple withholds the user's name (returning users, reinstalls, TestFlight builds): a short "One more step" name-entry screen appears and the flow resumes automatically once both names are entered.
- Users with an approved, purchased, rejected, or previously issued RSVP can now submit a fresh request for the same event. Only a pending (actively under review) RSVP blocks a new submission — previously any prior RSVP in an active state permanently blocked re-application.
- Ticket tier availability on the organizer dashboard (web and mobile) now shows a **pending** count alongside the sold figure — e.g. "485 / 500 available · 6 Pending RSVPs" — so organizers can see at a glance how many slots are already claimed by pending or approved RSVPs before deciding to close or adjust capacity.
- The edit-tier warning banner on mobile now appears when there are pending RSVPs in addition to when tickets have been sold, with a message that lists both counts and the resulting minimum quantity allowed.
- My Tickets cards now treat the server-stored total as the source of truth for pending and approved RSVPs, so the price never drifts between the request screen, the card, and the bank statement. Every surface that shows a ticket price for an in-flight RSVP — request sheet, My Tickets card, organizer dashboard, Stripe — now reads from the same authoritative number.
- Added a small internal note clarifying that per-event service fee customization is configured via the event itself (the standard 10% + $0.99 remains the default for all new events). No user-facing change — this just keeps fees consistent across surfaces if a partner event ever uses a different rate.
- **My Tickets** (web and mobile) and the **organizer's Sent list** (web and mobile) now order entries by purchase date, newest first. Previously the order was inconsistent — newest tickets sometimes appeared mid-list — making it hard to find a ticket you just received or a complimentary you just sent.
- Discover page now supports up to **10 events** in the Featured Events carousel — the previous database constraint that allowed only one featured event at a time has been removed. Featured cards are sorted by event start date so the closest upcoming featured event always appears first. Web and mobile share the same cap.
- The big "Reserve Your Spot" spotlight card on Discover (web and mobile) is now driven by a separate **Main Featured** flag, decoupled from the Featured Events carousel. An event can be featured in the carousel, set as the main spotlight, both, or neither — and the database enforces at most one main featured event at a time. When no event is set as main featured, the spotlight falls back to the closest upcoming event so the slot is never empty.
- Mobile Explore Organizers row no longer caps at 10 organizers — it now matches web at **30**, so newly approved organizers show up immediately without waiting for a release. Web's Discover page organizers list is also bumped to 30 for parity.
- Mobile Settings now has a **Scan Tickets** entry at the top, available to everyone — signed in or not. Event staff with an access code from the organizer can scan tickets directly from the app without needing a Flame account, mirroring how `flme.co/qr-scanner` already works on the web. The full scanner flow (validate code → scan QR → confirm check-in) uses the access code as the credential end-to-end.
- Ticket tier cards on mobile now use a tighter, more readable type scale — the stage name (primary title) and tier name (sub-line) each drop down one step in size, and inter-row spacing is tuned per row so the header pair sits tight while the description and price stay visually separated. Long stage and tier names render more cleanly on smaller devices.

## Batch 2 — Org rework (web + mobile)

### Improvements

- Redesigned the mobile bottom tab bar into a single unified set of tabs — Home, Search, My Tickets, and User — replacing the old split between attendee and organizer tab bars. The same five destinations now appear for every user regardless of role.
- Added a new User tab that opens a personal profile screen with avatar, email, edit-profile link, and the full list of organizations the user belongs to. Tapping an approved org opens that org's admin screen; pending orgs render as disabled rows with a "Pending approval" label.
- Added a dedicated Organizer Admin screen per organization, reached from the User tab. The screen shows the org logo, name, city, Instagram, total events, total revenue (with multi-currency support), a Stripe status pill for owners and admins, and action tiles for QR Scanner, Team, RSVPs, and Create Event (each gated by the user's role within that org).
- Redesigned the public organizer page (opened from Discover or a shared link) with a new 2-column event grid, location and Instagram in the header, a Past Events accordion, and a cleaner share flow.
- Moved the Create Event action off the tab bar and into the Organizer Admin screen. Event creation is now always scoped to the org the user explicitly opened, fixing cases where the old global Create button could flicker between orgs or create an event under the wrong organization.
- Moved the Settings cog into the persistent top header next to the notifications bell so settings are one tap away from any screen. The old attendee/organizer role toggle pill has been removed entirely.
- Notifications and deep links now carry the organization context, so tapping a push notification for a specific org always lands you in that org's screens with the correct role and permissions applied — no more flicker to a previously-selected org while the app catches up.
- Stripe Connect status is now shown as a small pill on the Organizer Admin screen instead of a full-width banner. Owners and admins see "Stripe Connected" in green or "Stripe Not Connected" in amber and can tap to manage their payout account.
- Stripe payout settings now confirm which organization is being managed on every state (not connected, setup incomplete, fully connected), so organizers with multiple orgs can never misidentify which account they are about to connect or adjust.
- Darkened all search bars in the app to match the dark input style used on event creation. The previous white search bars drew too much focus on dark screens.
- Added an error state with a Retry button on the personal profile screen so users whose organizations list fails to load can recover without restarting the app.
- Replaced the blank loading screens on the personal profile page and the organizer admin page with shape-matching placeholders (avatar, organization rows, stat cards, action tiles, event cards). The page structure now appears immediately instead of a centered spinner, matching the loading pattern used by Stripe, Instagram, and other modern mobile apps.
- Web app now matches the mobile org-rework end-to-end. The web navigation is rebuilt around the same destinations (Discover, My Tickets, Profile, plus a Settings cog and a QR Scanner icon next to the avatar). The old "Hosting View" pill and the floating settings button on My Tickets are gone — settings live in the top navbar now.
- Added a new web Profile page (`/profile`) that shows the user's avatar, name, email, the list of organizations they belong to with an event count next to each, and a "Create new organizer" entry. Tapping an approved organization opens that org's admin page; pending organizations show a "Pending approval" label and stay disabled.
- Added a new web Organizer Admin page that mirrors the mobile screen: org logo and name, location and Instagram, total events and total revenue, a Stripe status pill for owners and admins, and an action tile row for Team, RSVPs, and Create Event (each gated by the user's role within that org). Includes a "Go Back" link to the Profile page.
- Added a public organizer page on the web (`/organizer/<slug>`) reachable from the Discover page's Explore Organizers chips — anonymous visitors can view an organizer's profile, current and upcoming events in a 2-column grid, and past events behind an accordion, plus share the page link.
- Organizer details (Instagram handle, city, description) are now editable from the web Settings → Organization tab for owners and admins, with a Save button and an immediate "Saved" confirmation. Non-admin members see the same fields read-only.
- Added a full Team management page on the web (`/organizer/team`) that matches mobile: list of all members with role badges and event-assignment counts, invite a member by email with role selection (Admin or Organizer), change roles, assign specific events to organizer-role members, and remove members with a confirmation. Owner/admin only.
- Adding or editing a team member's role on web now offers Admin and Organizer only — matching mobile. Existing viewer-role members keep displaying correctly, but the role is no longer assignable from either platform.
- Replaced the previous full-width "Payment Account" banner on the web organizer admin page with the same compact Stripe status pill used on mobile — green "Stripe Connected" for fully connected accounts, amber "Stripe Not Connected" for accounts that need attention (tappable to manage payouts).
- Removed the per-event detail "Capacity / Sold / Revenue / Remaining" stats row on the web organizer event-detail page — it didn't exist on mobile and made the screen feel out of sync. Event statistics still appear inside the rolled-up admin dashboard cards.
- Web event-detail page now formats dates and times in the **event's own timezone** rather than the viewer's local timezone, matching how mobile has always behaved. A cross-timezone event (e.g. an Ecuador event viewed from Los Angeles) no longer renders a day off.
- Search bars across the web app (Home, Discover, My Tickets, RSVPs, organizer admin) are now uniformly styled to the dark input pattern used on event creation. The previous white search bars drew too much focus on dark screens.
- Web organizer event cards on the admin page now show Attendees, Revenue, and a "View Details" link in the same shape as mobile, instead of a simpler list row that omitted those numbers.
- The "By X" organizer name on the public event-detail page is now plain text (it briefly became a hyperlink during the rework). The single entry point to an organizer's public page is tapping the chip in the Discover section's Explore Organizers row.
- Anonymous (signed-out) users can now visit an organizer's public page directly without being redirected to sign in. The previous behavior accidentally protected the public route alongside the admin routes.

### Fixes

- Fixed a flash of the "Host your own events" banner at app launch for users who already have an approved organization — the banner now waits for the membership check to finish before rendering.
- Fixed a rare navigation trap on shared organizer links: tapping back on the public organizer page when the app was opened directly from a link (no previous screen) now returns you to Home instead of becoming a no-op.
- Fixed the public organizer page occasionally showing a "ghost" organizer profile with generic placeholder name and empty metadata while the organization details were still loading. The page now shows a proper loading state and an explicit "Organizer not found" message when the slug does not match any organization.
- The Instagram link on an organizer's public page now fails gracefully when Instagram is not installed, instead of surfacing an unhandled error.
- Fixed pull-to-refresh on the Organizer Admin screen so it refreshes co-host assignments and invited-event data alongside the org, events, and revenue stats — previously co-host badges could stay stale after pulling to refresh.
- Fixed pull-to-refresh on the public organizer page so it refreshes the org profile and past events in addition to the current events list.
- Fixed the Stripe onboarding return screen on mobile showing a "Redirecting to your dashboard…" message that referred to the old dashboard tab. The message and error copy now say "profile" to match the new navigation.
- Fixed a case where switching between organizations quickly could cause the admin screen to momentarily show action tiles or permissions from the previous organization before the new org's role resolved. Role-gated buttons now wait for the correct organization's permissions to load before rendering.
- Fixed a case on the organizer admin screen where re-opening a recently visited organization could leave the action tiles and Stripe status pill stuck on the loading placeholder until the page was pulled to refresh. Role-derived UI now releases as soon as the role is confirmed for the open organization.
- Fixed the Total Revenue card on the organizer admin screen briefly flashing through "$0" before settling on the real value. The card now waits for both the events list and the live revenue data to be ready before displaying anything; if the live revenue lookup fails, it falls through to the existing "Revenue estimates shown" tier-derived estimate.
- Fixed the Stripe status pill on the organizer admin header popping in late and shifting the layout. The pill's slot is now reserved with a placeholder while Stripe status loads, so the header keeps a stable shape from the moment the page mounts.
- Fixed the action tile row on the organizer admin screen briefly showing only the QR Scanner tile before the rest of the tiles (Team, RSVPs, Create Event) appeared. Tiles now render together once the user's role for the open organization is confirmed, instead of progressively appearing as data arrives.
- Fixed organizer-role members on both web and mobile seeing every event in the organization rather than only the events explicitly assigned to them. The organizer admin screen, the RSVP management screen, and the event lists everywhere in between now filter to the assigned-events set; organizers also no longer see the org-wide Total Events and Total Revenue cards (those remain for owner/admin only). The RSVPs tile is also now visible to organizers — previously they only saw the QR Scanner tile, leaving no entry point to manage RSVPs for the events they were assigned to.

## Batch 3 — Co-hosts, tier controls, and access-code unlock flow (OTA)

<!-- Once a binary release happens for this batch, rename this file to v1.0.14.md -->

### Improvements

- Organizers can now pick **which registration form questions apply per ticket tier** (web and mobile). Tiers default to inheriting all event fields, or organizers can pick a subset — so different ticket types can ask different questions (e.g. dietary preferences on VIP only) without bloating every checkout. Tier-effective fields drive both the attendee form and required-field validation.
- Standardized mobile checkout error styling on the brand red — required-field borders, error text, the checkout error banner, and the promoter-invalid icon now use a single design-system token instead of the legacy magenta.
- **Co-hosts on web parity with mobile.** Organizers can now add and remove co-host organizations directly from the web event-management screen, with the same search + assignment flow that's been on mobile. Co-hosted events now appear on the co-host org's dashboard with real attendee and RSVP counts (not just on the owner's), and co-host org admins can scope individual organizers to specific co-host events from the Team page.
- **Co-host visibility everywhere.** Events with co-hosts now show "Co-host with {org}" pills on the organizer dashboard, the public event page, and the discover/profile pages. Co-hosted events appear under each contributing organization's public profile — not just the owner's.
- **RSVP badge unified across surfaces.** RSVP-required events now display a consistent pill in the top-right of every event card (organizer dashboard, home, profile). When a card is both a co-host event and RSVP-required, the badges stack cleanly.
- **Organizer profile loading polish (mobile).** Replaced inconsistent placeholder shapes with a card-grid skeleton matching the actual event grid (Luma/Eventbrite pattern). Past events only render when they exist — no more empty-section placeholders for orgs without history. Pull-to-refresh now also refreshes co-host membership.
- **Public organizer profile counts now include co-hosted events.** The "N events" pill on `/organizer/[slug]` now reflects owned + co-hosted (matching the dashboard listing) instead of owned-only.
- **Mark a tier sold out or hide it (web + mobile).** Organizers can flag a tier as sold out — attendees see "Sold Out" while existing tickets and pending RSVPs stay intact — or hide a tier entirely so it disappears from the attendee event page but remains visible and manageable on the dashboard.
- **Tier and stage descriptions (web + mobile, create + edit).** Organizers can add an optional description to each ticket tier and each price stage. On the attendee event page, the active stage's description takes precedence over the tier description when both are set.
- **Reduce capacity with confirmation.** Lowering a tier's quantity below its reserved count now prompts a "Reduce capacity?" confirmation instead of hard-blocking. Confirming cancels the affected checkout holds and pending RSVPs, releases any pending Stripe authorizations, and notifies those attendees; sold tickets are never touched.
- **Clearer reserved labels.** Organizer tier and stage rows now read "N reserved" (active holds + pending RSVPs) instead of "Pending RSVPs", and each price stage shows its own reserved count.
- **Access-code unlock flow (web + mobile).** Ticket tiers with a secret code are now hidden from the event page by default; attendees enter the code in a new "Access Code" input below the tier list to reveal and auto-select the hidden tier — matching the Eventbrite/Dice pattern. The previous pre-checkout modal is removed. The unlock is verified server-side; hold and RSVP routes re-check the code at submission time as a defense-in-depth measure. Organizers can set `is_hidden` and `secret_code` at tier-creation time (create-event and add-tier flows) as well as when editing an existing tier. A contextual hint appears when a code is set on a visible tier, reminding organizers to enable "Hide tier" for the code to take effect.
- **"Access Code applied" indicator in checkout.** After unlocking a tier, every checkout surface — the mobile checkout sheet, the web inline RSVP payment modal, and the web direct-purchase page — now shows a read-only green "applied" container for the access code, consistent with how promo codes and promoter codes are already displayed throughout checkout.

### Fixes

- Fixed mobile checkout not validating required registration fields client-side — attendees could submit with empty required questions and only see a generic server error. Inline red error text now appears under each missing required field and blocks submission, matching web.
- Fixed the web registration form modal showing **"Invalid input: expected string, received undefined"** for empty required fields. The message now reads "This field is required".
- Fixed the web event-edit page showing **"All N event fields"** for a tier even after a subset was saved — the organizer fetch was missing the per-tier field column, so saved subsets weren't reflected in the UI (the database row was always correct; this was a read-side display bug only).
- Fixed co-host org admins seeing an empty RSVPs tab after navigating back from an individual RSVP detail screen on web — the selected-org sync only fired on the Dashboard tab, so direct tab landings stayed stale.
- Fixed the web event-management "Co-hosts → Manage" button being visible to co-host orgs viewing an event they don't own — the API correctly rejected the action, but the button is now hidden from non-owner views.
- Fixed the public organizer profile (`/organizer/[slug]`) potentially exposing draft events. Every other public events surface in the app already filters by `status = published`; this one now does too.
- Fixed a TypeError that briefly appeared when a co-host opened a co-hosted event detail on web (`.map is not a function`) — caused by a React Query key collision between two different cohost queries.
- Improved a11y on the web co-host assignment modal — added dialog semantics (`role="dialog"`, `aria-modal`, `aria-labelledby`) and Escape-to-close, matching the rest of the app's modal pattern.
- Fixed mobile event creation dropping the tier description — new events created on mobile now save their tier descriptions (the field was silently omitted from the create payload), matching web and the mobile edit flow.
- Fixed the attendee tier card hiding descriptions on most tiers — a description now always shows when set, instead of only on tiers without a per-person limit.
- Fixed the mobile tier-availability check evaluating the manual "sold out" flag before the sales window, so a tier's scheduled open/close time is now respected consistently with web.

## Batch 4 — Quick Wins (OTA)

Summary: a bundle of small, high-value polish fixes across discovery, organizer tools, and My Tickets.

### Improvements

- Home and Discover (web and mobile) now open filtered to **Quito** when it has events, so the most relevant local events show first. The active city appears as a pill next to the search bar; tap it to switch city or clear to all cities. Once you change the filter it stays where you left it.
- Adding or editing a ticket tier from the manage-event screen (web and mobile) now **pre-fills the sale-end date to the event's end time**, matching event creation — one less field to fill in for the common case. An end date you set yourself is always kept.

### Fixes

- Fixed promo codes piling up and overlapping on the mobile organizer Promotions card when an event had several codes — they now stack as full-width rows, matching the promoter links list.
- Fixed the mobile **Send Tickets** flow hiding the configure step at the bottom of the screen: selecting a recipient now scrolls the tier/quantity/Send block into view, and the keyboard no longer covers the field you're typing in. On web, the "Step 2: Configure" block now scrolls into view when you pick a recipient.
- Fixed a new ticket or RSVP not appearing on **My Tickets** (mobile) right after checkout — the list now refreshes automatically, with no pull-to-refresh needed.

## Batch 5 — Bank-transfer custom price, ticket-PDF emails & no-account sends (OTA)

Summary: organizers get a custom-price option on bank-transfer orders, complimentary and bank-transfer emails now carry the ticket PDF, and tickets can be sent to people who don't have a Flame account.

### Improvements

- Organizers can now set a **custom price** when creating a **bank-transfer order** (web and mobile). Toggle "Set custom price", enter an amount, and the order, PDF, and email all reflect it — useful for negotiated rates or partial payments. Left off, the order uses the tier/stage price as before.
- **Complimentary and bank-transfer emails now attach the ticket PDF** with a scannable QR per ticket, just like paid orders — recipients no longer have to open the app to get in. A multi-ticket complimentary send arrives as one email with a page per ticket.
- Organizers can now send a **complimentary ticket or a bank-transfer order to an email that isn't a Flame account** (web and mobile). When a search finds no Flame user, a "Send/Create without a Flame account" option appears; the recipient gets the ticket PDF by email and scans it at the door. (They can still claim it in the app later by signing up with that email.)
- The web QR scanner's **"Scan Next Ticket"** now returns straight to the live camera instead of the "Activate Camera" screen, so door staff can scan ticket after ticket without an extra tap — matching mobile.

### Fixes

- Fixed the **complimentary-ticket PDF QR not scanning** at the door — the emailed PDF's QR was missing data the scanner needs, so it was rejected even though the in-app QR worked. Complimentary PDFs now scan on both the app and web scanners. (Re-send any complimentary tickets issued before this fix to get a scannable PDF.)
- Fixed the **mobile organizer Sent list** (Send Free Ticket and Bank Transfer Orders) not updating after a send — a freshly sent ticket now appears immediately, with no pull-to-refresh.

## Batch 6 — Org-approval admin surface (OTA)

Summary: support staff get a pending/rejected organization queue on their profile to approve, reject, or delete new organizers — no more manual database edits.

### Improvements

- **Support staff can now approve, reject, or delete pending organizations** directly from their profile (web and mobile). Below "Create new organizer", an allowlisted support account sees a **Pending approvals** list and a **Rejected** list, each with one-tap actions.
