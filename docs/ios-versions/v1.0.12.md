# Changelog — v1.0.12

Summary: ships App Store compliance changes addressing v1.0.11 review feedback (Guidelines 4.8 and 5.1.1(v)), plus RSVP, uploads, and account UX improvements.

---

## Fixes

- Fixed a database rule that blocked a new RSVP for the same event after a prior RSVP was rejected or expired — only active statuses conflict now, so users can re-apply from the event page; the rejection email mentions submitting again if details were wrong.
- Fixed Terms and Privacy links on mobile sign-up failing silently when the in-app browser could not open — errors are logged so support can diagnose "tap does nothing" cases.
- Improved RSVP rejection emails for paid RSVPs: they now explain what happened to the payment — authorization hold released (nothing charged), refund issued, or team follow-up if the payment is still settling. Amounts and card details come from Stripe server-side, with typical bank timing (5–10 business days) and a support contact for questions.
- Fixed iOS event image uploads chopping 4:5 posters — the native crop tool was forcing a square crop that clipped title and date blocks. Picking a poster that is already 4:5 now uploads the artwork with its framing preserved; sources at other aspect ratios are center-cropped to a 4:5 canvas on upload (so some edges may be cropped), matching the web behavior.
- Fixed "Event not found" errors when an organizer in multiple organizations uploaded an event image — uploads now resolve the event by its unique id rather than by slug, so organizers who manage multiple orgs with overlapping slugs are no longer blocked.
- Prevented two published events from ever sharing the same public URL — the database now enforces a single published event per slug, so `/events/{slug}` always resolves to exactly one event.

## Improvements

- Sign in with Apple is now available on mobile alongside Google and email, including Hide My Email support so ticket and account emails still reach relay addresses.
- Delete Account is available under Settings → Personal on mobile and web with a two-step confirmation; eligible users can remove personal data while ticket and tax records stay valid, and organizers with active events or sales are guided to support instead of self-deleting.
- New account creation on mobile now requires Terms of Service and Privacy Policy acceptance; sign-up buttons (Apple, Google, Create Account) appear dimmed until the box is checked and tapping one beforehand highlights the checkbox in red, so it's always clear what's pending.
- Raised the organizer image upload limit on web from 1MB to 4.5MB for event posters, org images, and profile images, with API checks, storage limits, and on-screen hints updated (WebP included where supported).
- Event detail pages now display posters in a full 4:5 ratio (Instagram portrait) on both web and mobile. Posters that are already 4:5 (the recommended 1080×1350 export from design tools) display with their framing preserved; posters at other aspect ratios are center-cropped to 4:5 on upload, so some edges may be cropped.
- Editing an event on mobile now previews the image in the same 4:5 frame it will be stored and displayed at, so the preview matches the uploaded result.
